# Choose tables and record counts

Use this guide to decide which tables a run will populate and how many rows it will request for each table.

## Before you start

- Connect SeedBomb to the intended Dataverse environment.
- Use a non-production environment where you can create test records.
- Know which tables you want to populate, including any related tables whose newly generated records should supply lookups.

## Select the tables

1. Open **Generate** and go to **Select tables**.
2. Enter a display name or logical name in **Search tables**. The list shows both names, so check the logical name when two tables have similar labels.
3. Optionally enable **Custom only** to narrow the list to maker or ISV tables. First-party tables such as `msdyn_*` do not count as custom for this filter.
4. Check each table you want to populate. Check the **Selected** list and **Total** on the right.
5. Uncheck a table to remove it, or choose **Clear** to clear the selection.
6. Choose **Next** to open **Volume & rules**.

Filtering the list does not clear checked tables. Review the Selected list before proceeding.

## Set the volume and run settings

1. Under **Rows per table**, enter the desired count for each selected table. The app accepts **1–100,000 rows per table**. For a first attempt, use a small count such as `10`.
2. Set **Seed** if you want to retain the same generation seed for later runs.
3. Leave **Locale** as displayed; this version uses English and has no locale picker.
4. Set **Batch size** between `1` and `1,000`. This is the number of rows grouped into a create batch, not the total rows to create.
5. Set **Parallelism** to `0` for automatic selection, or a value from `1` to `16` for a configured limit.
6. If particular field values are required, open the rules link and follow [Customize field values and lookups](field-rules.md).
7. Choose **Next** and inspect **Review** before starting a run.

Existing counts are preserved for tables that remain selected. Removing and later reselecting a table creates a new count entry using the configured default; check it again.

For example, selecting Account with `10` rows and Contact with `20` rows plans `30` new rows. Batch size `10` changes how those rows are sent; it does not change the planned total.

## Handle related tables

SeedBomb analyzes lookup relationships **between the tables you selected** and orders generation around those dependencies. It does not automatically select every related table.

- Select a lookup's target table too when you want the automatic lookup handling to use records generated by this run.
- To refer to existing records instead, add an explicit lookup rule: **constant**, **one-of**, or **random (existing records)**.
- Constant and one-of lookup rules supply their own record identities and remove that lookup from the automatic dependency calculation. An optional null rule also removes the dependency. **random (existing records)** retains dependencies on selected target tables because it can use records created earlier in this run when no existing candidates are available.

Required lookups still need a usable value. Review checks unsupplied SystemRequired lookups: a target supplied automatically must have all its allowed target tables selected for creation before the source, and cannot be a self-reference. For a blocker, select the needed target tables or configure a constant, one-of, or random lookup rule. Random lookup candidates receive a further check at Start run. See [Customize field values and lookups](field-rules.md).

## Expected result

Review reflects your selected tables, counts, and rules. Selecting tables and changing settings creates no Dataverse records; writes begin only after **Start run** on the Run step.

Keeping a seed is useful for controlled testing, but a seed alone does not guarantee identical records across environments or runs: metadata, rules, run-ID tokens, and the existing records available to lookup rules can differ.

## If something goes wrong

| Problem | Action |
| --- | --- |
| Table list fails to load | Check the active connection, then choose **Retry** in the table picker. |
| A table cannot be found | Clear the search and turn off **Custom only**; confirm you are connected to the right environment. |
| The total is unexpected | Review all selected tables, including tables hidden by the current search, and check their counts. |
| Review shows a blocker | Correct the named rule, count, or lookup before continuing; a preview does not prove Dataverse writes will succeed. |
